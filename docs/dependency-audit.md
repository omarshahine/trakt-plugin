# Development dependency audit (2026-11-04)

PR #39 head `3196663da2e96c656620f7a5077f9eb88e1d4477` and base main `4e2a634e11576a7ac370b56ec4d68e69beecfc3d` have identical dependency manifests and lockfiles. The reported findings predate this PR. Fresh npm advisory data reproduced 18 affected package nodes (2 critical, 10 high, 5 moderate, 1 low). These counts include parent packages affected through dependencies; they are not counts of independent advisories.

`npm audit --omit=dev --json` reports zero vulnerabilities before and after this change. The published plugin has one direct runtime dependency, `@sinclair/typebox`; OpenClaw is an optional peer supplied by the host and a development dependency used for SDK types. The audit does not establish that an independently installed OpenClaw host is secure.

## Compatible fixes

- Pin the development SDK to OpenClaw `2026.6.6`, the next security patch compatible with the existing Node 22 minimum. This fixes [GHSA-3x84-qq85-fj65](https://github.com/advisories/GHSA-3x84-qq85-fj65), a CDP discovery blocked-WebSocket bypass. Runtime peer compatibility remains unchanged.
- Constrain tsup's esbuild dependency to `0.27.2`, which satisfies tsup's `^0.27.0` range and predates the affected `>=0.27.3 <0.28.1` range for [GHSA-g7r4-m6w7-qqqr](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr). This is a Windows development-server arbitrary-file-read issue; the build uses the CLI bundler. The constraint prevents reintroducing it on lockfile refresh.

## Remaining SDK development findings

The final audit reports 17 affected development package nodes (2 critical, 10 high, 5 moderate). Every remaining node is below `node_modules/openclaw`. OpenClaw publishes an npm shrinkwrap; tested root overrides and a non-forced npm update did not replace its pinned vulnerable tree. Those ineffective overrides are not included.

Do not force SDK-internal dependency upgrades or hand-edit its shrinkwrap. The current stable SDK `2026.10.10` raises its Node requirement to `>=24.16.0 <25 || >=26.1.0`, while this plugin supports Node `>=22.19.0`. Its metadata also pins `zod@4.6.5` and `minimatch@10.2.6`, both still affected by current advisories. A larger SDK/toolchain migration needs separate compatibility review and does not by itself guarantee a clean audit. Current tsup `9.0.0` is a major upgrade; no forced major upgrade is included.

The remaining advisories affect SDK HTTP servers, trust/URL handling, archive and glob processing, validation, or parsing. The plugin tests mock the SDK entry; the plugin does not call these host-server, archive-installation, or browser implementations. They remain real risks when the development SDK executable or affected libraries process untrusted input, so a clean production audit must not be described as a clean full audit.

This is the version explicitly installed by the successful [main plugin CI run](https://github.com/omarshahine/trakt-plugin/actions/runs/41899310907). Both inspector npm scripts invoke the local executable, and the inspector workflow uses `npm run plugin:ci`. `npm ci` now obtains the inspector and its transitive dependencies from the committed lockfile rather than resolving a new inspector release through unversioned `npx` at execution time.

The added tooling increases the lockfile development graph from 394 to 407 nodes. Fresh full and production-only audits have the same results: 17 affected development package nodes (2 critical, 10 high, 5 moderate), zero production findings, and no new advisory packages. The OpenClaw shrinkwrap assessment above remains unchanged.
